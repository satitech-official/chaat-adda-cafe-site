# Contributing to Sati Technologies repositories

Thank you for taking the time to improve a Sati Technologies project.

## Before starting

1. Search existing issues and pull requests to avoid duplicate work.
2. Open an issue for significant changes before implementation.
3. Do not publish client-confidential information, credentials, personal data or unlicensed assets.
4. Keep each change focused on one problem.

## Development workflow

1. Create a branch from `main` using `feature/short-name`, `fix/short-name`, `docs/short-name` or `chore/short-name`.
2. Follow the repository's setup instructions.
3. Add or update tests where practical.
4. Run linting, tests and a production build locally.
5. Use clear commit messages, for example `feat: add mobile navigation`.
6. Open a pull request and complete every relevant section of the template.
7. Respond to review feedback and keep discussion respectful.

## Quality expectations

- Preserve responsive behavior and accessibility.
- Avoid unnecessary dependencies.
- Do not weaken security checks.
- Update documentation when behavior changes.
- Include screenshots for visible interface changes.
- Never commit `.env` files, tokens, private keys, production datasets or customer information.

By contributing, you confirm that you have the right to submit the work and that it does not violate a client agreement or third-party license.
